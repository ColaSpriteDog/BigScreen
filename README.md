# BigScreen

生产监控大屏与数据编辑页面。大屏沿用现有设计，主要适配 1440 × 720；编辑页使用 Vue 3 + Element Plus，后端使用 Flask + SQLite。

## 启动

在项目目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

已安装依赖后，也可以双击 `启动.cmd`。

- 编辑页面：<http://127.0.0.1:8080/edit>
- 登录页面：<http://127.0.0.1:8080/login>，首次启动默认账号 `admin`、密码 `admin123`。登录后可在“员工管理”修改。
- 联网大屏：<http://127.0.0.1:8080/screen>
- 健康检查：<http://127.0.0.1:8080/api/health>

数据库默认保存在 `data/dashboard.sqlite3`，首次启动创建表和固定产线/工序配置，业务数量初始为空。先在编辑页录入并保存，再由大屏展示。重启服务不会清空已保存数据。

其他局域网设备访问 `http://服务电脑IP:8080`，首次使用需放行服务电脑的 TCP 8080 端口。默认通过 Waitress 监听 `0.0.0.0`，适用于受信任的现场局域网。大屏公开展示，后台页面、原始编辑数据及全部写接口均需员工登录；会话有效期为 12 小时。

员工管理支持新增、修改、停用和删除，所有启用员工均可编辑业务数据及管理员工。密码按要求明文保存在 SQLite 中，已有密码不回传页面，修改时留空保留原密码。停用、删除或改密使旧会话失效；修改当前账号密码后保留当前会话，其他会话失效。禁止删除或停用当前登录账号。已有数据库启动时自动增加账号表并创建初始账号，业务数据保持不变；重启不会重置员工账号和密码。

可指定端口及数据库位置：

```powershell
.\.venv\Scripts\python.exe server.py --port 8088 --database D:\BigScreenData\dashboard.sqlite3
```

业务时区在“流程与设置”页面修改，初始默认为 `Asia/Shanghai`（中国标准时间）。业务日期、停机区间和安全天数统一采用该时区。

## 编辑与展示

- 录入人、录入时间、最后修改人和时间由后端自动记录，无需手填。表格末列显示“最后修改”，整体表单在标题处显示；悬停、键盘聚焦或点击可查看首次录入和最后修改详情，时间按业务时区展示。
- 每次保存只更新实际变化记录的修改人及时间；没有变化的行、只调整排序和直接重复保存均保留原人员信息。新增未保存行显示“未保存”，已有未记录人员的旧数据显示“历史数据”，不补造录入人。
- 人员信息使用保存时的员工 ID 和姓名快照，员工改名、停用或删除后仍保留原姓名。客户端提交的人员信息不参与保存，公开大屏接口不返回这些信息。人员信息与业务数据一起提交或回滚。

- 编辑页使用固定模块侧栏、浅色表格和底部保存栏，五个模块分别保存；小屏改为顶部导航，宽表在表内滚动。
- 未保存字段和行以浅绿标记，底栏显示实际修改数；字段恢复原值后取消标记。放弃修改需确认，取消后保留草稿。
- 固定四条产线，名称和标准日产量在“流程与设置 → 产线配置”中编辑，历史日报及停机关系按固定 ID 保留。
- 在产线配置中勾选“显示到趋势图”，支持任选 1～4 条产线，至少保留一条；新建数据库默认选中 A/B 拼焊线，已有选择保持不变。
- 生产日报按日期维护四条产线数量，支持历史补录。落料线以米记录产量、报废长度和标准，其他三线以件记录。大屏产线卡片显示业务时区昨日的产量、报废量和不良率，昨日未录入时显示“—”，运行状态和运行率按当天计算。本月产量和当月趋势来自同一份日报，均按业务时区本月 1 日至今天统计；同单位产线绘制堆叠柱，每种单位仅用一条白色折线显示实际总量，米与件使用独立纵轴、分别累计，四条产线颜色按 ID 固定。趋势中的未录入产量按 0 展示并参与合计与累计，原始日报保留空值。
- 生产日报点击“导入生产日报推移图”，月份默认业务当前月，可修改。读取“激光切割”“机器人点焊”“激光焊接”“激光焊接 (B)”四表，按 C 列为 1 日解析；数量和报废按白夜班明细汇总，同时提取白夜班工时及拼焊异常停机小时。预览显示工时、停机及源错误；超过班次工时、误放报废率公式等错误不参与 OEE，产量仍可导入。有效工时替换原默认值，缺失工时保留原值；数量或工时有差异时需勾选覆盖。日报、原始理想节拍及标准同事务提交，重复导入不累加，不改写实时停机区间；未来日期、源数量错误、标准不一致和版本冲突拒绝保存。
- 停机时段支持多段、跨天、维护/故障及未结束记录；可手填起止时间，也可使用“开始停机”和“恢复运行”。
- 生产日报每条产线可填写当天“计划生产时长 / 小时”，默认 24，支持 0～24 小数；填写 0 表示当天不安排生产，运行率显示“—”。不需要填写班次起止时间，历史日期可补录，各日期和产线独立保存，并自动记录修改人。
- 运行率＝（计划生产时长－当天累计已发生停机时长）÷计划生产时长，分母不随当前时刻变化，最低为 0%。停机按业务日截取、重叠时段合并，只扣已发生部分；由于不填写班次时间，当天登记的全部停机都参与计算。停机状态仍在时段结束后自动恢复。
- 大屏原材料明细显示产品名称、规格型号、剩余数量、重量和可切数量；半成品明细显示类别（左件/右件）、产品名称、规格型号、剩余数量，连续同类记录合并类别单元格。库存单位放在表头，同类库存有多种单位时按单位分列；后台仍保留物料类型、仓库和单位。编辑页支持手工编辑和 Excel 导入。
- 在库存明细或销售出货页面点击“导入仓库日报”，只选择一次 `.xls` 或 `.xlsx`，同时读取“汇总表”和“成品出库明细”。出货月份默认业务当前月，可在入口选择其他月份。汇总表中钢卷归入原材料，左件和右件归入半成品；“产品名称”对应原材料部位或半成品物料，“剩余数量”直接作为库存，不用累计入库减累计出库重算；重量和可切数量空白时保持为空。
- 一次预览原材料、半成品及所选月份出货，点击“确认导入”后在同一事务中保存两类业务并更新大屏，无需分别导入或分别保存。库存按完整快照替换，出货按所选月份完整明细替换，未列出的原记录和对应未保存草稿会被替换；订单量和其他月份数据保留。取消预览不改草稿，任一表解析或保存失败时两部分都不更新。相同物料沿用已有 ID 和仓库，多个仓库匹配时提示歧义。
- Excel 仅解析提取，后台不保存上传文件；单文件最多 160 MiB。读取 Excel 已保存的公式结果，不执行宏和公式，请先在 Excel 中重新计算并保存，再导入。预览接口不写库、不改变版本或录入人员信息，保存沿用现有并发校验和人员记录。
- 原材料数量支持小数；可切为用户填写的件数。库存状态、零库存项数和按单位汇总自动计算。
- 原材料重量在编辑页、导入预览和大屏统一以吨显示，原始 Excel 与接口字段 `weight_kg` 仍按千克保存，显示时除以 1000、编辑时换回千克，保留空白和零值。半成品数量统一以件显示，源表及历史数据中的“个”映射为“件”，数量不变。
- 统一导入中的“成品出库明细”按出库日期筛选所选月份；逐行提取日期、零件号、名称和数量，重复件号也保留多条记录，不合并、不按数量排名，重复导入不累加。导入后仍可在库存和销售页手工修改。
- 当月订单量单位为件。大屏“当月销售出货统计”按零件号汇总出货数量，降序展示 TOP 8 型号横柱图；同件号忽略大小写合并，并列时按件号排序。月累计及达成率由全部明细计算，编辑页和导入仍保留逐条记录。编辑页搜索只筛选列表，不改变累计口径。旧版月累计记录原值保留，缺少出库日期和名称的历史记录不会被自动拆分或补造。
- 全局指标全部由 A/B 两条激光拼焊线日报自动计算，无需另行录入。大屏累计业务当月月初至今天的实际产量，计划量按已录入产量的产线日累计当前标准日产量（不按计划生产时长折算），综合达成率为累计完成量除以累计计划量；未录入产量不计计划，明确录入零产量计入计划。任一已录入产线缺少标准时，计划量和达成率显示空值。品质合格率为（累计实际产量－累计报废量）÷累计实际产量，保留两位小数；有产量的日报缺少报废量，或累计实际产量为零时显示空值，明确零报废正常参与计算。平均产出为累计实际产量÷对应日报累计计划生产工时，单位为件/时；A/B 工时分别累计，未录入产量的日报不计工时，明确零产量计入工时，总工时为零或无日报时显示空值。导入工时采用源表已扣计划停机的白夜班工时之和，保留原始精度。OEE 按时间开动率×性能效率×品质率计算，并以合格品理想工时÷累计计划工时加权；异常停机单位为小时，不重复扣除计划停机。源停机错误、未导入理想节拍或缺少有效报废数据时 OEE 保持空值，源错误在预览中标明。修正源表后需重启后端并重新导入，存在差异时勾选覆盖。安全天数由起算日期自动计算。
- 保存失败保留草稿，并自动定位到错误提示。版本冲突会提示重新加载；任一字段或表保存失败会回滚整批数据。
- 大屏每 5 秒读取一次。同一浏览器中保存还会立即通知大屏读取；断网时保留最后成功画面并显示连接中断。
- 库存内容超出时自动以每秒 10 像素滚动，首尾停留 2 秒，无暂停/继续按钮；鼠标停留不影响滚动，手动查看后会自动恢复，键盘聚焦时暂缓。
- 工序连接线以 1.6 秒周期向右流动；维护、故障或停机节点两侧变橙并静止，其他正常连接继续流动。状态恢复后自动重新流动；系统开启减少动态效果时保留静态连接。
- 桌面采用四等分网格：库存区与产线 01、销售区与产线 04 两侧边缘对齐，中间趋势和工艺区域跨两列。安全图标放大为 68 像素。

Vue、Element Plus、ECharts 和工序图片均从本地提供，运行时无需访问外部 CDN。前端不需要 Node.js 服务或打包步骤。

## 演示数据

仅在手动执行以下命令时生成，正常启动服务不会植入测试数据：

```powershell
.\.venv\Scripts\python.exe demo_data.py
```

命令先使用 SQLite 在线备份保存原数据库，再在一个事务中写入近 30 天的四条产线日报、8 条原材料、10 条半成品、12 个出货件号及全局指标。产线名称、业务时区、趋势选择和已有安全起算日期保留；当天 B 线生成一段维护时段用于观察工序联动。

原数据备份保存在 `data/backups/dashboard-before-demo-*.sqlite3`，具体路径由命令打印。重复执行覆盖相同周期的演示值，不重复累加数量。恢复原数据时先停止服务，再以所需备份替换数据库。

## 测试

开发测试依赖：Python 3.10+、Node.js 18+（仅用于 JS 单元测试）及 Chrome/Edge。Node.js 不参与业务服务运行。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe run_tests.py
```

没有安装 Chrome/Edge 的测试电脑可先安装 Playwright Chromium：

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

所有业务测试使用隔离的临时 SQLite，不写入正式数据库。测试日志与 JUnit XML 位于 `output/tests`，浏览器验证截图位于 `output/playwright`。测试范围及实测结果见 `docs/TEST_REPORT.md`。

## 项目文件

- `bigScreen.html`：保留的原始设计参考，本次未修改。
- `templates/screen.html`、`static/js/screen.js`：联网大屏。
- `templates/editor.html`、`static/js/editor.js`：数据编辑页面。
- `backend/schema.sql`：结构化业务表及员工、会话配置表，没有 `data_json` 存储列。
- `backend/auth.py`：员工账号维护、登录会话及默认账号初始化。
- `backend/audit.py`：逐记录实际变更判断、首次录入及最后修改人员信息。
- `templates/login.html`、`static/js/login.js`：员工登录页面。
- `backend/domain.py`：日期、停机时段和输入校验。
- `backend/service.py`：业务保存、事务和汇总计算。
- `backend/__init__.py`：页面及 API；接口说明见 `docs/API.md`。
- `server.py`：Waitress 启动入口。
- `static/vendor/SOURCES.txt`：本地前端依赖来源和校验值。

数据库使用 WAL 模式。备份时使用 SQLite 在线备份接口，或完全停止服务后复制数据库及其相关文件。
