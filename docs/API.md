# 接口与数据口径

页面与接口由同一个 Flask 服务提供。写入请求使用 `application/json`，成功返回新版本；错误返回 `{"error":"中文错误信息"}`。

除 `/api/health`、`/api/dashboard` 和 `/api/auth/login` 外，全部 API 均要求登录 Cookie，未登录或会话失效返回 HTTP 401；`/edit` 未登录跳转 `/login`。跨站来源的写入返回 403。员工会话有效期 12 小时；停用、删除或改密后旧会话失效。大屏及其读取接口公开。

## 版本与事务

编辑页使用统一“导入仓库日报”入口。一次上传同时预览两张业务表，再确认统一保存，不再分别选择库存和出货文件。预览任一工作表出错即整批拒绝；保存时任一业务校验失败或版本冲突均不更新任何业务表或录入人员信息。取消保留原草稿，确认会替换库存和所选月份出货及对应未保存草稿，不影响其他月份。旧单模块预览接口仍可供独立 API 调用。

库存预览单文件最多 160 MiB（请求体额外允许 1 MiB 表单开销），其余 JSON 接口仍限制 2 MiB。上传在内存中解析，Waitress 输入缓冲与上传限额一致，不保留文件。按表头识别“物料名称、产品名称、规格型号、剩余数量、单位、剩余总重量、预计可切割数量”；剩余数量必填，重量与可切数量允许为空，合并的左右件分组向下沿用。公式只读取缓存结果，缓存缺失、错误单元格、非法数量及重复记录均返回中文错误和源行号。`raw/semi` 可作为库存草稿，经原有 `PUT /api/inventory` 保存。

每个写入请求必须携带读取时得到的 `version`。版本不一致返回 HTTP 409，保留服务端原数据，编辑页保留未保存草稿。

同一模块的一次保存使用 SQLite `BEGIN IMMEDIATE` 事务；任意校验或数据库约束失败都回滚，成功后统一递增版本。大屏读取同一数据库快照，避免读到跨表的半批数据。

## 员工账号

首次启动创建 `admin / admin123`，已有业务数据库也自动补建账号表，重启不重置密码。所有启用员工均可编辑数据及管理员工。账号为 1～40 位英文字母、数字、下划线、点或短横线，不区分大小写；姓名为 1～40 字；密码按要求明文保存，最长 128 字。员工列表不回传已有密码。

`PUT /api/employees` 示例：

```json
{"version": 0, "employees": [
  {"id": 1, "username": "admin", "name": "管理员", "password": "", "enabled": true},
  {"username": "worker01", "name": "张三", "password": "123456", "enabled": true}
]}
```

新员工不传 `id` 且必须设置密码；旧员工密码留空表示保留原密码。禁止删除或停用当前登录账号。停用、删除、修改密码均撤销目标员工旧会话，重新启用也不恢复旧会话；修改当前登录员工密码会保留此次会话。

## 业务表

数据库按字段保存，没有 `data_json` 数据列。

| 表 | 保存内容 |
|---|---|
| `production_line` | 固定产线编号、名称、标准日产量、设备理论小时最大产量、关联工序、趋势显示范围 |
| `production_daily` | 日期、产线、实际产量、不良数量、计划生产小时数；日期与产线联合主键 |
| `line_downtime` | 产线、停机起止时间、原因、备注；结束时间可空表示未结束 |
| `raw_material_stock` | 物料、仓库、规格、部位、库存、单位、重量 kg、可切件数 |
| `semi_finished_stock` | 类别、物料、仓库、规格、库存、单位 |
| `sales_month` | 月份、订单件数 |
| `shipment_month_item` | 月份、出货日期、件号、名称、数量及顺序；同件号允许多条明细 |
| `daily_overview` | 日期及全局计划、完成量、设备综合效率、品质合格率、平均产出 |
| `process_node` | 工序名称、现有切图路径、顺序，以及钢卷/出货两个独立工序状态 |
| `screen_settings` | 统一业务时区、安全起算日期、数据版本、最近保存时间 |
| `employee` | 员工账号、姓名、明文密码、启用状态及会话版本 |
| `auth_settings` | 持久化登录签名密钥，使重启后有效会话保持可用 |
| `record_attribution` | 业务表与主键定位的首次录入人、录入时间、最后修改人及修改时间；姓名独立保存，不随员工改名或删除变化 |

原材料重量字段 `weight_kg` 始终为千克，编辑、预览及大屏界面换算为吨（÷1000），编辑吨数时换回千克提交。半成品的历史单位“个”和导入源表的“个”统一映射为“件”，数量不变；读取时不直接改写数据库，后续保存使用“件”。

## 只读人员信息

编辑数据和员工列表记录增加 `_audit` 字段；客户端不需要提交该字段，即使提交也会被忽略。操作人仅由已校验的登录会话确定，时间来自服务器时钟。

```json
{
  "state": "saved",
  "created_by_id": 1,
  "created_by_name": "管理员",
  "created_at": "2026-11-23T12:00:00+00:00",
  "modified_by_id": 2,
  "modified_by_name": "张三",
  "modified_at": "2026-11-23T13:00:00+00:00"
}
```

`state=unsaved` 表示尚未录入的空白日报/指标/月订单；`state=legacy` 表示已有数据但历史人员未知，仅返回状态。历史数据首次修改后开始记录修改人，创建人及创建时间保持 `null`。明确的数量 `0` 属于实际录入值。

`production.lines[*]._audit` 记录所选日期的日报归属，`_configuration_audit` 单独记录固定产线配置归属；`production.overview._audit` 为全局指标；停机、库存、出货、工序、员工列表的每行分别带 `_audit`。`settings._audit` 为时区及安全设置，`sales._audit` 为所选月份订单量归属，均与列表行独立。

人员信息在业务事务内按保存前后的规范化字段比较，仅业务值变化的行更新最后修改人。版本号递增、保存时间刷新及列表排序不会覆盖行归属；保存失败或版本冲突不写入人员信息。出货记录保存后保留已有 ID，传入 ID 必须属于当前月份；未传 ID 的旧客户端按当前月份及件号匹配。删除记录同时清理归属，复制的新记录重新记录创建人。

旧数据库启动时自动补建 `record_attribution` 表，不修改原业务数据。公开 `/api/dashboard` 不包含人员信息。该功能保存首次录入与最后修改，不保存逐次操作历史。

## 日报请求

`GET /api/editor` 中的 `production` 可作为草稿基础，保存时再加上 `version`。`lines` 必须包含四条固定产线，每项提供 `id`、`actual_qty`、`defect_qty`、`planned_hours`；缺失产量用 `null` 表示。

产线 01 单位固定为米，`actual_qty`、`defect_qty`、`standard_qty` 接受非负小数；其他三线单位固定为件，数量必须为非负整数。读接口通过 `lines[*].unit` 返回单位，落料线的 `defect_qty` 表示报废米数，不良率分子分母均以米计量。

大屏 `GET /api/dashboard` 的 `production_date` 为业务时区昨日日期，产线卡片使用 `yesterday_qty`、`yesterday_defect_qty`、`yesterday_defect_rate` 显示昨日实际产量、报废量及不良率。昨日未录入时返回 `null`，明确录入的 `0` 保留；不回退到更早日期。`actual_qty`、`defect_qty`、`defect_rate` 仍为当天值，运行状态和运行率按当天计算，本月累计与趋势范围保持原口径。

生产导入默认业务当前月份，允许修改；固定模板 C 列为 1 日，按月份天数读取。短月份多余列中的标准模板值忽略，实际或报废有非零数量则拒绝，不能静默丢弃。对应工作表为“激光切割”→01、“机器人点焊”→02、“激光焊接”→03、“激光焊接 (B)”→04。切割汇总白夜班切割长度与报废米数；点焊汇总 R4/R5/R6 白夜班；拼焊汇总左右件白夜班。标准按相同范围求和并同步更新配置；各日标准不一致时拒绝导入，因为当前标准为固定日产量。

导入读取标准、实际、报废和白夜班工时的已保存值，不执行宏、公式和批注。工时行分别为切割 24/34、点焊 21/39、拼焊 23/36，拼焊工时公式已扣除计划停机，保留源小数精度，不按显示的 10.2 小时反推。部分数量明细缺失按零求和，全天实际明细全空则跳过，不覆盖原日报；报废全空时保留已有值。实际明细明确填零属于可导入数据。预览允许勾选日期和产线；未来日期不可保存。`overwrite` 默认 `false`，数量、工时或异常停机与已有非空值不同时需明确勾选覆盖。工时有效时更新 `planned_hours`，缺失或错误时保留原值，新日报仍使用默认 24；预览 `warnings` 标明源问题，异常停机无法核实时清空该日导入的停机值，OEE 返回空值，数量仍可导入。实际停机区间不被文件改写。重复导入不累加，人员归属仅在实际变化时更新；非法提交或旧版本整批回滚。理论产能只在产线配置维护，导入不推算节拍、不覆盖理论产能。文件仅驻留内存，限额沿用 160 MiB。

拼焊异常停机明细取白班 28/33 行、夜班 41 行及 45/46 行附近唯一标为“异常停机工时”的行，单位全部为小时；不叠加班次合计行。空白停机按该明细未填停机即零处理，负数、超过对应班次工时或左右件合计超过班次工时均在预览标明，停机值保持 `null`。带百分号格式或误放报废率公式（如 `C44/C43`）的停机单元格不作为小时使用，必须修正源表。左右件停机应按不重叠时长填写，只有累计小时无法从文件重建重叠区间。

`planned_hours` 为该日期、该产线的计划生产小时数，取值 0～24，支持小数（界面保留两位小数），不能为 `null`、空串、布尔值或字符串。默认 24；0 表示无生产计划、运行率为空值。旧客户端未提交此字段时保留该日已有计划，没有日报时默认 24。该字段与产量、停机及人员信息在同一事务中保存，非法时整批回滚；补录历史日报不改变今天计划。

已有数据库启动时自动补建 `planned_hours` 列，历史记录默认为 24，不重写业务数量、停机或录入/修改人；非默认计划时长本身也属于实际录入，并记录人员信息。

`overview` 提供 `planned_qty`、`actual_qty`、`completion_rate`、`oee_percent`、`quality_percent`、`average_output`，全部由 A/B 激光拼焊线（固定 `line_id` 为 3、4）的日报计算，均可空。提交同名全局字段不参与保存，历史手填全局值保留在库中但不参与展示。编辑接口返回所选日派生指标，草稿实时预览；大屏累计业务时区当月月初至今天的数据，不计未来日期及其他月份。

日报的 `abnormal_hours` 为异常停机小时，编辑允许补录零至本日计划工时，未提交时保留旧值，缺失不推断为零。产线配置新增可空 `theoretical_max_per_hour`（设备理论最大产量），单位为落料线米/小时、其他产线件/小时，必须为大于零的数字，支持小数，留空表示未配置；旧客户端未提交时保留原值。新旧数据库均不自动推算理论产能。编辑接口中的 `ideal_cycle_hours` 为当前配置的 `1/theoretical_max_per_hour`，供草稿预览使用；旧日报存储的导入节拍仅留档，不再参与 OEE。Excel 导入及普通日报保存均不能改写理论产能，标准日产量仍只用于生产目标与达成率。配置保存后，历史和本月 OEE 均按当前理论产能重新计算，不重写原始日报或其人员信息；如设备生产不同产品，当前配置须对应所统计产品的节拍口径。

停机记录示例：

```json
{
  "line_id": 4,
  "start_at": "2026-11-21T11:00:00",
  "end_at": "2026-11-21T13:00:00",
  "kind": "maintenance",
  "note": "设备维护"
}
```

`kind` 支持 `stopped`、`maintenance`、`fault`。已有记录需带 `id`，从本日列表移除的已有记录会被删除。跨天记录可从相交的任一天编辑。重复覆盖的停机区间按时间并集合计，不重复扣减。

## 计算规则

- 运行率使用固定的 `planned_hours` 分母：`max(planned_hours×3600－当天已发生停机秒数, 0) ÷ (planned_hours×3600) × 100`；计划为 0 返回 `null`，午夜无停机且计划大于 0 时为 100%。分母不随当前时刻变化。
- 当天累计停机按业务日边界截取，未结束记录仅计算至当前时刻，未来部分不提前扣除，重叠时段合并。不区分班内和班外停机。历史日报按所选日期的计划及全天已发生停机统计，不混入当天数据；编辑页“当前状态”仍展示产线实时状态。
- 停机状态按 `[开始时间, 结束时间)` 判断；结束时自动恢复。未来时段尚未发生时不提前停机或扣减运行率。
- 未指定偏移的日期时间按配置的业务时区解释，数据库统一保存 UTC。接口也接受带偏移的 ISO 日期时间；夏令时不存在的时间会拒绝。
- 原始日报中未录入数量保留 `null`，明确录入的 `0` 才代表零产量；趋势展示将未录入产量按 `0` 返回，库存口径不变。
- 产线月累计来自当月已录入日报。趋势使用业务时区本月 1 日至今天及配置勾选的 1～4 条产线，默认选择 A/B 拼焊线；日期轴连续展示当月已到日期，跨月自动重新累计。同单位产线以堆叠柱展示，每种单位只显示一条合计折线。米与件使用独立纵轴和堆叠组，不混加；`trend.groups` 每项提供 `unit`、`totals`、`period_total`。单单位时顶层 `totals/period_total` 保留对应值，多单位时为 `null`。缺失产量按 `0` 参与每日合计与累计；全部未录入时合计与累计均为 `0`。`reported_days` 统计任一所选产线实际录入数量的日期数，明确录入 `0` 也计入。
- 全局完成量仅累计 A/B 拼焊线的 `production_daily.actual_qty`，不混加激光切割米数和机器人点焊件数。计划量按每条已录入非空实际产量的产线日累计对应 `production_line.standard_qty`，不按计划时长折算；明确零产量也计入计划，空白日报不计。标准使用当前配置，修改标准会重新计算历史日报的派生计划量；任一已录入产线缺少标准，计划量返回 `null`。综合达成率由累计完成量除以累计计划量，不取每日达成率的平均值；累计计划量为空或为零时返回 `null`。
- 品质合格率使用相同日期范围的 A/B 拼焊日报，按 `SUM(actual_qty-defect_qty)÷SUM(actual_qty)×100` 计算，保留两位小数，不取每日合格率的平均值。任一有产量的日报 `defect_qty` 为 `null` 时返回 `null`，明确零报废正常参与计算；零产量记录无待判定产品，不因报废空白影响其他日报。累计实际产量为空或零时返回 `null`，全部报废时返回 `0`。
- 平均产出使用相同日期范围、`actual_qty IS NOT NULL` 的 A/B 拼焊日报，按 `SUM(actual_qty)÷SUM(planned_hours)` 计算，单位为件/时，保留两位小数，不取各日日均产出的平均值。分母使用日报计划生产工时，不扣除停机时间；同一天 A/B 两条线的工时分别累计，空白产量不计工时，明确零产量计入工时。工时默认沿用日报的 24 小时，可逐日按产线修改；累计工时为零或没有日报时返回 `null`，有工时且累计零产量时返回 `0`。
- OEE 按相同范围已录入的 A/B 日报汇总，计划工时为 `SUM(planned_hours)`，运行工时为 `SUM(planned_hours-abnormal_hours)`；不重复扣除源工时公式已扣的计划停机，也不与实时停机区间叠加。理论节拍为当前产线配置 `1/theoretical_max_per_hour`（小时/件），开动率为运行工时÷计划工时，性能为 `SUM(actual_qty/theoretical_max_per_hour)`÷运行工时，品质按理想工时加权为 `SUM((actual_qty-defect_qty)/theoretical_max_per_hour)`÷`SUM(actual_qty/theoretical_max_per_hour)`。三者乘积等价于 `SUM((actual_qty-defect_qty)/theoretical_max_per_hour)÷SUM(planned_hours)×100`，保留两位小数；不同理论节拍不直接平均 OEE。任一已录入产线缺少理论产能，或日报缺少有效停机、报废或有产量但零运行工时，整月 OEE 为 `null`；有计划且零产量可为 `0`。结果超过 100% 时保留原值，需核对配置产能、工时及数量，不自动截断。
- 原材料与半成品按单位分别汇总，不混加卷、张、件等单位。重量和可切件数为空时显示“—”。
- 出货记录按 `shipment_date` 筛选对应月份，保存 `part_no`、`name`、`quantity`，按草稿顺序保留每条明细；同一件号可以有多条记录。月累计对全部明细求和；大屏 `sales.ranking` 按件号忽略大小写汇总数量，按数量降序、件号升序取前八项，每项包含 `part_no` 和 `quantity`，供横柱图显示。`sales.items` 及编辑、导入数据继续逐条保留。
- 出货预览复用库存上传的 160 MiB 限额和内存解析方式，返回 `items`、`month`、`source_count`、`shipped_qty`、`available_months`。应用到草稿后通过原保存接口整体替换当月明细；保留订单量，其他月份不受影响。旧表自动升级并保留原记录 ID、数量和人员记录，历史月累计没有日期时返回 `null`。
- 出货保存的 `items` 每项包含 `shipment_date`（`YYYY-MM-DD`，必须属于目标月份）、`part_no`、`name`、`quantity`；已有行带 `id`。预览另带 `source_row` 定位源行，重复件号和完全相同的源行均逐条保留；源表其他月份不参与当月累计。旧接口未传日期和名称时保留已有值，新建历史兼容记录的日期为空。
- 本月订单量的单位为件，出货达成率使用相同数量口径。
- 安全天数为业务日期与起算日期之差，起算当天为 0 天。
- 生产相关工序状态取关联产线的当前状态；单独 B 线维护时显示“B线维护”。钢卷、出货状态在设置页独立维护。

出货排名 `sales.ranking` 每项另提供 `name`：同件号的非空名称按明细顺序去重，以 ` / ` 连接，名称全空时返回空字符串。横柱图在件号下方显示名称，悬浮提示展示完整名称；数量汇总与排序口径保持不变。

## 趋势产线配置

`trend.series` 每项提供 `has_data`，表示该产线在业务时区本月 1 日至今天是否录入过非空实际产量，明确录入 `0` 也为 `true`。趋势标准产量仅汇总同单位、所选且 `has_data=true` 的产线；B 线日报全空时只计 A 线，B 线录入后自动恢复合计。全空或参与汇总的产线缺少标准时不绘制标准线，柱图、图例与实际产量合计保持原有口径。

`PUT /api/settings` 的 `lines` 中可以提交 `show_in_trend`，支持布尔值或整数 0/1；四条产线中必须至少选中一条。未提交该字段的旧客户端会保留已有选择。保存失败时，名称、标准产量、选择和版本一起回滚。

`GET /api/editor` 的 `production.monthly_plan` 返回 `{month, planned_qty, _audit}`，可通过 `production_month=2026-11` 选择生产月份，默认业务当月，不受日报日期和销售月份影响。`PUT /api/production/<day>` 可随日报提交 `monthly_plan: {month: "2026-11", planned_qty: 28000}`；数量为 0 至 1000000000000 的整数，`null` 或空字符串表示清空，未提交 `monthly_plan` 时保留原计划。大屏月总计划优先使用对应月份非空的计划，清空或未设置时沿用日报累计；综合达成率使用相同分母，明确零计划时达成率为 `null`。月计划按月份持久化并记录修改人员，与日报及版本在同一事务内保存，不影响下方按日指标；流程与设置不再维护月计划。

产线名称可编辑，固定 ID 不变，不重新创建日报和停机记录。大屏柱状系列名称、图例、相关停机告警使用当前名称，颜色按固定 ID 分配。合计折线名为“所选产线合计”，累计值也只统计所选产线。
